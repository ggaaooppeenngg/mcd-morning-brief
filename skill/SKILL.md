# 麦麦晨报（McDonald's Morning Brief）

把麦当劳的营销活动、可领优惠券、积分到期、抽奖机会聚合成一份 30 秒读完的晨报，
可直接作为个人 Agent 每日晨报的一个栏目（例如插在天气和日程之间）。

## 前置条件

用户需在 MCP 配置中启用麦当劳官方 MCP Server（Token 申请：https://open.mcd.cn/mcp）：

```json
{
  "mcpServers": {
    "mcd-mcp": {
      "type": "streamablehttp",
      "url": "https://mcp.mcd.cn",
      "headers": { "Authorization": "Bearer ${MCD_MCP_TOKEN}" }
    }
  }
}
```

## 晨报生成流程

按以下顺序调用工具（前两个必调，其余按需；一个部分失败不要中断整份晨报，
在该栏目位置标注"暂未获取到"即可）：

1. `now-time-info` — 获取今天日期，后续所有"还有 N 天"以此为准
2. `campaign-calendar` — 当月活动日历；筛选出**进行中**与**未来 7 天内开始**的活动，
   按开始时间排序；对未来的活动标注"⏰ N 天后开始"
3. `available-coupons` — 麦麦省可领优惠券列表；只报告名称、力度、有效期，**不要自动领取**
4. `query-my-coupons` — 我的优惠券；挑出 **7 天内到期**的，单独提醒
5. `query-my-account` — 积分账户；重点报告**即将过期积分**及过期日期
6. `query-lottery-info` — 抽奖活动；仅当活动进行中且有免费次数时提醒

## 输出模板

严格按下面的结构输出 Markdown（空栏目直接省略，不要输出"无"）：

```markdown
## 🌅 麦麦晨报 · {今天日期 星期X}

### 📅 近期活动
- 🔥 **进行中** {活动名}（{MM.DD} ~ {MM.DD}）
- ⏰ **N 天后开始** {活动名}（{MM.DD} 起）

### 🎫 今日可领优惠券（N 张）
- 🎟️ **{券名}**｜{力度}｜有效期至 {MM-DD}

### ⌛ 即将过期的券（N 张）
- 🎟️ **{券名}**｜有效期至 {MM-DD}

### 💰 积分
- 可用 **{可用积分}** 分｜累计 {累计积分} 分
- ⚠️ {N} 积分即将过期（{日期} 前），别浪费啦

### 🎰 抽奖机会
- 🎁 「{活动名}」进行中，你还有 N 次免费抽奖机会

---
> 数据来自麦当劳 MCP Server，仅供参考；以麦当劳 APP / 门店实时信息为准。
```

## 后续意图处理

晨报发出后，用户可能直接回一句，按以下方式处理：

| 用户说 | 动作 |
|---|---|
| 「领券」/「都领了」 | 复述将领取的券 → **必须得到确认** → `auto-bind-coupons` → 汇报结果 |
| 「我的积分」 | `query-my-account`，报告可用/即将过期，过期分给出去建议（如积分商城兑换） |
| 「抽一下」 | `query-lottery-info` 确认有免费次数或明确告知消耗 → **确认后** → `draw-lottery` → `query-my-prizes` 报告奖品 |
| 「这活动怎么参加」 | 用 `campaign-calendar` 中该活动的说明回答；信息不足就建议查麦当劳 APP，不要编造规则 |
| 「明天/本周有什么活动」 | 重跑流程 1-2，调整筛选窗口 |
| 「导出日历」 | 引导使用本仓库 CLI：`python -m mcd_brief calendar --ics mcd.ics`（可导入手机日历） |

## 安全与合规守则

- **所有会改变账户状态的操作（领券、抽奖、下单）必须先经用户确认**；晨报本身只读。
- 不自动下单；用户要下单时建议其在麦当劳 APP 完成支付环节。
- 不编造活动规则、价格、库存；工具没返回的就说没拿到，引导官方渠道。
- 若连续两次工具调用失败，告知用户检查 Token 与网络后停止，不要空转重试。
- 免责声明固定附在晨报末尾。
